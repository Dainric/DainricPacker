### 3. 执行层重构 —— 消除参数类 bug 的结构性成因

新增 `Execution.cs`，核心是 **`BuildCommand` 不可变对象**：

```csharp
public sealed class BuildCommand
{
    public string Exe { get; }
    public IReadOnlyList<string> Args { get; }
    // 构造时就拒绝「参数里含可执行文件自身」
    // —— 这正是 PyInstaller 报 "unrecognized arguments" 的根因
}
```

之前 `List<string> prefix` 在各层之间传递，谁负责拆出可执行文件、谁负责拼参数是**模糊的**，
于是出现了「exe 同时出现在 exe 位置和参数列表里」。

现在：
- 命令只在构造处拼完整，`CommandRunner` **只接受成品，不做任何推断**
- 构造函数内**结构性拒绝**重复的可执行文件
- `Process.Start()` 之后立刻重设 `EnableRaisingEvents`（有注释说明原因）

### 5. 图标资源化 —— 源文件瘦身 58%

之前 `构建原生版.py` 用文本替换把 95 KB base64 硬塞进 `.cs`，
导致 `MainWindow.xaml.cs` 膨胀到 166 KB 且完全不可读。

现在改成 **EmbeddedResource**：

```xml
<EmbeddedResource Include="Assets\app.ico" LogicalName="Dainric.Packer.app.ico" />
```

```csharp
var s = asm.GetManifestResourceStream(name);   // 运行时读流，不再有 base64
```

结果：**166 KB → 70 KB**，diff 可读，构建脚本也不再做字符串手术。

### 6. 打包失败诊断（BuildDoctor）

**用户价值最高**的一项。打包失败时原来只丢一段几百行的原始日志，
现在自动识别 12 类常见失败模式并给出结论：

| 识别模式 | 给出的因果 |
|---|---|
| `ModuleNotFoundError` | 缺模块 → 填 hidden-import 或先安装 |
| `Failed to load Python DLL` / `api-ms-win-crt` | 缺 VC++ 运行时 |
| `Can't find a usable init.tcl` | Tcl/Tk 数据文件缺失 |
| `PermissionError` / `Access is denied` | 文件被占用或无写入权限 |
| `being used by another process` | 旧程序还在运行 |
| `UnicodeEncodeError` / `codec can't encode` | 路径含非 ASCII 字符 |
| `Failed to execute script` | **是产物启动失败，不是打包失败** |
| 超时 | 建议调大超时并说明大库耗时 |
| `hook-*.py ERROR` | 第三方库的钩子失败 |
| 递归过深 / spec 语法 / 磁盘空间 | 各自的处理建议 |

输出形如：

```
诊断结果
----------------------------------------------------
打包失败

可能原因
  · 脚本导入了未安装（或未被自动收集）的模块

建议处理
  · 在「高级参数」里把缺失的模块填进 hidden-import
  · 或先安装它：pip install <模块名>
  · 若模块是运行时才导入的，必须手动加 hidden-import
```

### 7. 运行时获取方案

python.org 在本机不可达，实测发现：

- `nuget.org` 可达 → 但 Python 的 NuGet 包**不含 tkinter/tcl**（只 42 MB），弃用
- `mirrors.aliyun.com` / `registry.npmmirror.com` / `mirrors.huaweicloud.com` 都可达

最终方案：从**阿里云镜像**取官方安装包，静默免注册安装到指定目录：

```
python-3.12.10-amd64.exe /quiet InstallAllUsers=0 TargetDir=... \
  PrependPath=0 Shortcuts=0 Include_launcher=0 Include_tcltk=1 Include_pip=1
```

验证：Python 3.12.10 · Tk 8.6.15 · pip 25.0.1 · PyInstaller 6.22.3，
**能构建并运行 tkinter 程序**。

## 五、已知限制（如实说明）

1. **绿色包只带 3.12**。若某库反而需要 3.13/3.14，需用户自备环境后用
   「从文件夹导入」挂进来。程序已支持，但这一步需用户手动操作。
2. **运行时不含 numpy/pandas 等重型库**。目标脚本用到时，需把包装进
   `runtime-py312/Lib/site-packages/`，或导入一个已装好的环境。
3. **未做代码签名**，打包产物仍可能被杀软误报。
4. **`BuildDoctor` 是基于经验的正则匹配**，不是穷举。
   未匹配到时会退化为「列出日志末尾 + 建议用控制台模式」，不会硬猜。
5. `MainWindow.xaml.cs` 仍有约 70 KB，界面逻辑可再按页拆分
   （本轮未做，避免在功能收尾阶段引入大范围改动）。
