# 原生 Windows 版打包器 · 实现说明

作者 Dainric ｜ 真正的原生 EXE，不是「打包成 EXE 的 Python 脚本」

---

## 一、先厘清两种「EXE」的区别

这是整件事的关键，之前做错方向就是没分清：

| | 之前做的（PyInstaller） | **现在做的（原生）** |
|---|---|---|
| 本质 | Python 脚本 + 打包器自解压壳 | C# / WPF 编译的原生程序 |
| 启动 | 解压到 `%TEMP%` 再跑解释器 | 直接加载，无解压 |
| 依赖 | 内嵌 CPython 运行时 | .NET 运行时（自包含时也不需要） |
| 体积 | 32 MB（onefile）/ 42 MB（onedir） | **60.2 MB，单文件** |
| 特征 | 二进制里能搜到 `python`、`PyInstaller` | 搜不到 |
| 杀软误报 | 高 | 低 |
| 改一行代码 | 改 .py | 改 .cs/.xaml 重新编译 |

实测确认新 EXE 里**搜不到 `python` 和 `PyInstaller` 字符串** —— 它就是原生程序。

## 二、技术栈

```
.NET 9 SDK  +  WPF  +  C#
     ↓  dotnet publish -r win-x64 --self-contained
DainricPacker.exe   60.2 MB   单文件   目标机无需装任何运行时
```

选 WPF 而不是 WinForms/WinUI 的理由：

- **WinUI 3** 要 Windows App SDK，部署复杂，还不支持单文件自包含
- **WinForms** 做不出 iOS 那种圆角/发丝线/缓动
- **WPF** 原生支持 XAML 样式、矢量 Path、Storyboard 缓动、圆角 Border，
  且 `--self-contained` 单文件成熟稳定

## 五、它怎么打包

```
DainricPacker.exe  ──spawn──>  pyinstaller  ──>  目标.exe
   (原生, 不含 Python)           (需要目标机有)
```

**重要**：原生程序负责**界面与流程编排**，真正的打包动作仍然由目标机上的
PyInstaller 完成。因为「把 Python 脚本变成 EXE」这件事本质上需要 Python 工具链。

引擎探测按优先级查找：

1. 程序目录下的 `runtime\python.exe`（绿色版自带运行时）
2. `PATH` 里的 `pyinstaller.exe`
3. `PATH` 里的 `python.exe` → 用 `-m PyInstaller`
4. 常见安装位置（`%LOCALAPPDATA%\Programs\Python`、`C:\Python3xx`）

找不到时界面会明确提示 `pip install pyinstaller`，不会静默失败。

**语法检查**同理：有 Python 解释器就用 `py_compile` 预检，没有就跳过（不阻塞打包）。

## 六、踩到的两个坑（都是构建期才发现）

### 1. `InvariantGlobalization=true` 会让 WPF 启动即崩

为了减小体积我开了这个选项，结果启动直接异常退出（code `0xE0434352`）：

```
System.TypeInitializationException:
  The type initializer for 'MS.Internal.FontCache.MajorLanguages' threw an exception.
  ---> System.Globalization.CultureNotFoundException:
       Only the invariant culture is supported in globalization-invariant mode.
       en is an invalid culture identifier.
```

WPF 的字体缓存内部会构造 `"en"` 这个 culture，而 invariant 模式把非 invariant
culture 全部移除了。**结论：WPF 项目绝不能开 `InvariantGlobalization`。**

我是靠给 `App.xaml.cs` 加全局异常捕获 + 写 `crash.log` 才拿到精确堆栈的 ——
不然只看到一个退出码，完全无从下手。

### 2. 命名 `RenderTransform` 在 `ControlTemplate.Triggers` 里引用会报 MC4111

```
error MC4111: 无法找到 Trigger 目标"sc"
```

想用 `ScaleTransform` 做 iOS 那种按下缩放，XAML 编译器不认。
最终改用**透明度分级**表达悬停/按下（0.88 / 0.66），视觉上同样干净，且零风险。

## 七、构建方式

```bash
python 构建原生版.py              # 自包含单文件，目标机免装 .NET（60.2 MB）
python 构建原生版.py --framework  # 依赖 .NET 9 桌面运行时，体积约 1-2 MB
python 构建原生版.py --run        # 构建后直接启动
```

脚本会自动从 `打包_v2.9.0.py` 里解出内嵌 ICO 写进项目，并注入 base64 常量
（这样运行时释放默认图标不需要外部文件）。

**前置条件**：`.NET 9 SDK`。可通过 `winget install Microsoft.DotNet.SDK.9` 安装。

> 注意：`dotnet` 首次运行需要在用户目录写配置（`~/.dotnet`、`%APPDATA%\NuGet`），
> 如果被安全策略限制会报 `UnauthorizedAccessException`。

## 八、目前的能力与缺口

**已实现**

- 原生单文件 EXE，无 Python 依赖，启动快
- 选脚本 / 拖拽载入 / 语法检查
- 输出名（含 Windows 保留名校验）、输出目录
- 单文件 / 目录（onedir）两种形态
- 自动 / 控制台 / 无控制台三档
- UAC 提权、清理临时文件、可配超时
- 图标：`.ico` 直接用，`.png/.bmp/.jpg` 用 WPF 解码器转 ICO
- 版本信息（生成 PyInstaller 版本资源文件）
- 实时进度（解析 PyInstaller 输出）、彩色日志、复制/清空、打开目录
- 中止打包、崩溃日志

**还没做**（下一步可选）

1. **批量队列** —— 侧栏已留位，点击会提示「下一版本提供」
2. **高级参数**（hidden-import / add-data 手填）
3. **依赖分析**面板
4. **打包历史**记录
5. **自带运行时**：把便携 Python 放进 `runtime\`，做成真正零依赖绿色版
   （代码已支持探测，只差放置运行时；体积 +约 45 MB）
