## 一、v3.2.1：先补「已承诺但没兑现」的体验（建议优先）

### 1. 日志面板增强（S）
现状：日志已能自动换行，但面板宽度固定 392（`MainWindow.xaml:125`），长日志仍大量折行；
日志没有导出、搜索、时间戳，关掉程序就看不到历史构建过程。

建议：
- 左右栏之间加 `GridSplitter`，日志宽度可拖；标题栏加「放大日志」按钮（全宽/浮层，Esc 退出）
- 「只看错误/警告」筛选 + 关键字搜索（高亮命中行）
- 每条日志加时间戳（可开关）、自动滚动开关
- 「导出日志」按钮 + 每次构建自动落盘
  `%LOCALAPPDATA%\Dainric\logs\yyyyMMdd-HHmmss_<脚本名>.log`
- 复制按钮支持「复制全部 / 复制错误段」

### 2. 打包历史持久化 + 可操作（S）
现状：`_history` 只是内存里的 `List<HistItem>`（`MainWindow.xaml.cs:2088`），
**关闭程序就清空**；而《使用说明》写的是「每次打包的记录」。字段也只有
时间/名称/结果/耗时，且名称被截到 14 字，没有脚本路径和产物路径。

建议：
- 存 `%LOCALAPPDATA%\Dainric\history.json`，上限 200 条，启动时加载
- 字段补全：时间、脚本完整路径、产物名、产物路径、大小、耗时、结果、失败摘要
- 列表支持双击/右键：打开产物目录、重新打包该脚本、复制诊断、删除单条
- 批量记录同样带脚本路径

### 3. 输出目录为空时的兜底是错的（S，小 bug）
现状：清空「目录」后回退到 `AppDomain.CurrentDomain.BaseDirectory`
（`MainWindow.xaml.cs:699-700` 和批量 `1946-1947`），产物会落到
`%LOCALAPPDATA%\Programs\Dainric`（安装目录），用户找不到；
这与项目里「默认输出目录不要改回程序目录」的设计决策直接冲突。

建议：兜底改为 `RuntimeManager.DefaultOutputDir()`（桌面 `Dainric产物`）；
输入框里允许填相对路径时相对默认目录解析。

### 4. 版本号与《使用说明》收口到一处（S）
现状：`使用说明.txt` 第 1 行还写着 **v3.1.0**，安装目录里的副本也是旧的；
版本号散落在 `DainricPacker.csproj`、`构建原生版.py:14`（`VER`）、
`setup.iss:12`（`AppVersion`）三处，本次「标题 3.2.0 / 日志 3.1.0」就是同类问题。

建议：
- `构建原生版.py` 从 csproj 读 `<Version>`，自动生成 ISS 的 `AppVersion`、
  绿色版目录名、使用说明版本行，并重新打包安装包里的 `使用说明.txt`
- 使用说明补上 v3.2.0 的批量/依赖检查/自检/重试矩阵等新能力

### 5. 快捷键、窗口记忆、深色标题栏、关于页（S）
现状：主窗口没有快捷键（只有版本对话框有 Enter/Esc）；窗口大小/位置、
上次选择的脚本与输出目录都不保存；顶栏没有「关于」入口；
标题栏颜色跟系统走，浅色主题下会出现白色标题栏配纯黑界面的割裂感。

建议：
- Ctrl+O 选脚本、F5/Ctrl+Enter 开始打包、Esc 停止、Ctrl+L 清空日志
- 保存窗口大小/位置、最后路径到 `%LOCALAPPDATA%\Dainric\ui.json`
- 点顶栏版本号打开「关于」：版本、构建时间、更新日志、打开日志/说明、复制诊断
- `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)` 固定深色标题栏

## 二、v3.3.0：真正提升打包成功率的功能（按价值排序）

### 6. 高级参数面板（M）——诊断文案已经指向它，但界面没有
现状：`BuildDoctor.cs:113/115` 会提示「在『高级参数』里把缺失的模块填进 hidden-import」，
但 XAML/C# 里没有任何高级参数入口，用户按提示找不到地方。

建议（折叠面板，默认自动）：
- hidden-import / collect-data / collect-binaries / collect-submodules
- `--add-data`、`--exclude-module`、UPX 开关、额外 PyInstaller 参数（白名单校验后透传）
- 与自动重试矩阵共存：手动项优先，自动项去重
- 保存为预设，可随单个脚本记住

### 7. 数据文件打包向导（M）——PyInstaller 用户最大痛点
脚本读 json/csv/图片/模板时，单文件模式下这些文件不会自动进包。

建议：
- 「附加文件/目录」列表 → 自动映射 `--add-data`
- 生成 `sys._MEIPASS` 的 `resource_path()` 代码片段，一键复制
- 静态扫描 `open(...)` / `__file__` / `os.path.dirname(__file__)` 并提醒
- 自检阶段在临时目录运行产物，专门抓「资源找不到」

### 8. 智能识别脚本 + 试运行（S/M）
现状：只有输出名自动填脚本名；`HasGui()` 仅用正则判断 GUI 库（`MainWindow.xaml.cs:1527`）。

建议：
- 读脚本里的 `__version__` → 预填「输出 → 版本」；解析 `argparse` description 作为提示
- 检测 tkinter/PyQt/PySide/wx/pygame → 建议无控制台；检测 `input()` / 必填参数 → 提醒用控制台
- 检测 `multiprocessing` → 提示加 `freeze_support()`（冻结后常见坑）
- 「试运行脚本」按钮：用当前运行时在控制台跑一遍，先确认脚本本身没报错

### 9. 结果卡片 + 一键操作（S）
现状：成功后只有状态卡「打包成功 / 耗时」，产物路径、大小、哈希都不显眼；
失败诊断只写在日志里，用户要手动复制。

建议：
- 成功卡：产物大小、总耗时、SHA256（可复制）、「打开位置」「运行产物」「复制路径」
- 失败卡：诊断摘要 + 「复制诊断」（含脚本、参数、退出码、关键日志，方便贴给 AI/同事）
- 自检失败时展示产物 stdout/stderr 片段

### 10. 批量打包增强（M）
现状：有队列和三宫格统计，但没有每项耗时/大小展示，失败后不能只重跑失败项，
结果也只有日志。

建议：
- 队列项显示状态/耗时/产物大小；双击打开产物目录
- 「只重跑失败项」；批量结束导出 CSV/HTML 结果表
- 可选：每个脚本单独设置窗口模式/图标（默认继承全局）

## 三、v4.0 / 按需储备

### 11. 命令行 / CI 模式（M）
`Dainric打包器.exe --build app.py --out dist --mode console --icon app.ico --selftest --json`
+ 退出码，方便脚本化和自动构建（现在只有隐藏的 `DAINRIC_BATCHTEST` 环境变量）。

### 12. 单实例 + 文件关联（M）
双击 .py 交给已运行窗口载入；安装包注册「用 Dainric 打包」右键菜单 / 发送到。
长打包期间重复打开程序也不会出现多个实例抢引擎。

### 13. 代码签名支持（M/L）
单文件 EXE 被杀软误报是《使用说明》里已承认的常见问题。
可选配置 pfx + signtool 给产物自动签名，或至少给「如何加白名单 / 提交误报」的引导页。

### 14. 自动更新（M）
「关于」页检查更新（GitHub Releases 或自有 JSON），下载、校验、运行安装包。
注意：应用是免管理员安装，更新逻辑要复用同一安装路径。

### 15. UI 回归 + 打包冒烟测试（M）
把本次「日志被截断」「标题和日志版本不一致」这类问题变成自动断言：
- 启动应用 → 逐页截图 → 与基准图比对（像素差异阈值）
- 用 4 个固定脚本跑一遍打包（成功/缺模块/用法错误/无 import），断言产物自检与日志
- 挂到 `构建原生版.py` 最后一步，版本发布前自动跑

## 四、推荐顺序

1. **本轮先做 v3.2.1 的 1、2、3、4**（约半天）：
   都是「会丢东西/会找错地方/承诺没实现」的问题，收益最大、风险最小。
2. **下一版做 6 + 7 + 8**（约 3–4 天）：
   高级参数 + 数据文件 + 智能识别，是真正拉开与其他 PyInstaller GUI 差距的三件套。
3. 视需要再做 11（CLI）和 12（文件关联），这两项对「天天用」的用户体验提升明显。

版本号建议：v3.2.1（纯体验补丁）→ v3.3.0（功能扩展），避免继续用 3.2.0 重新发版，
否则安装包/绿色版/关于页会分不清「修复前/修复后」。
