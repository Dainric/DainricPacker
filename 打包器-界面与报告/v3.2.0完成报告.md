## 一、三项修正

### 1. 产物自检的假阳性（需参数脚本被误判为崩溃）

**问题**：打的是需要命令行参数的脚本时，自检裸启动它 → Python 以退出码 2 退出
→ 程序报「产物启动失败」。产物其实是好的。

**修法**（两层）：
- `DependencyChecker.LooksLikeUsageError()` 识别用法错误
  （`usage:` / `required` / `unrecognized arguments` / `no such option` …），
  命中即按「通过」处理，日志说明「产物要求命令行参数才继续运行」
- 新增「自检参数」输入框，填了参数就带着参数跑完整流程

回归测试：5 条正向 + 4 条反向（真实崩溃**不能**被误认成用法错误）。

### 2. 依赖前置检查

**问题**：脚本 import 了本机没装的模块时，老流程是
打包 → 自检崩 → 诊断缺模块 → 补 hidden-import 重试 → 全都没用 → 弹窗。
模块根本没装，补什么都不可能找得到。

**修法**：打包前用 `ast` 扫 import，在**被检查的那个解释器里**验可用性，
分四类：标准库 / 本地 / 已安装 / 缺失。缺就拦下，给出模块名与安装命令。
另配「检查依赖」「安装缺失依赖」两个按钮（走阿里云镜像）。

实测：`delta.py import dainric_absent_zz` → 0.2 秒内被拦下。

### 3. 重试矩阵扩展

原来只救「缺模块」。现在四种修复动作累积重试（最多 4 次）：
`--hidden-import` / `--collect-data` / `--collect-binaries` / `--collect-submodules`。

库名从真实报错里抽：`site-packages\<库名>` 路径、`Hidden import "x" not found!`。
抽完归一化成顶层包（`PyQt5.sip` → `PyQt5`）。

已验证不存在的库名传给 `--collect-*` **不会**让 PyInstaller 失败（只警告），
所以重试不会越修越坏。

## 二、过程中挖出的既有真 bug

### bug 1：`CommandRunner` 丢短命进程的输出

`WaitForExit(超时)` 只等进程退出，**不等重定向流读完**。
PyInstaller 输出量大、耗时长，回调来得及派发；短命子进程（几十毫秒）会丢输出。

表现：依赖检查间歇性拿到空结果，测试里稳定复现（65 个测试里挂 3 个）。

修法：`WaitForExit(超时)` 返回后再补一次无参 `WaitForExit()`。
`MainWindow.RunProcess` 里本来就有这句，`CommandRunner` 漏了。

已加回归测试：连跑 12 次短命进程，输出不得为空。

### bug 2：标题栏版本硬编码

`MainWindow.xaml` 里写死 `v3.1.0 · 原生版`，升 3.2.0 后标题还停在 3.1.0。

修法：`MainWindow.AppVersionText()` 从程序集元数据读，版本只在 csproj 里维护一处。

### bug 3：`FindPythonForCheck` 不认集中目录

它只看「程序目录下的 runtime」和 PATH，而打包走的是 `RuntimeLocator`
（会搜 `%LOCALAPPDATA%\Dainric`）。装到用户目录后，语法检查与依赖检查会静默失效。

修法：优先取 `RuntimeManager.PickUsable(...)` 选出的运行时。

### 顺带修的

- 依赖检查的扫描脚本用 `utf-8-sig` 读：Notepad / PowerShell 存的 `.py` 带 BOM，
  用 `utf-8` 读会让 `ast.parse` 直接报错，整个依赖检查哑掉
- 子进程输出改用 **ASCII 标记**（`STD`/`LOCAL`/`OK`/`MISSING`），中文在 C# 侧映射。
  中文 Windows 上 Python 的 stdout 是系统 ANSI 码页（GBK），读取端按 UTF-8 解会全乱码，
  归类判断跟着一起失配 —— 这个坑踩过一次，别再让中文跨进程边界
- 依赖页原来内嵌了一段等价的 Python 扫描脚本，已合并到 `DependencyChecker` 一处实现
- `BuildDoctor` 的 `collect-submodules` 规则必须排在 `hidden-import-hint` **之前**：
  `Analyze` 是「全部命中」而不是「首个命中」，两条规则匹配同一行，顺序决定谁先抽到库名
- `IsTopModule` 用子串判断而非等值：正则从 `site-packages` 里只能吃到 `site`，
  等值比较会漏
