作者：Dainric

## 一句话

界面与后端全部用 C++ 重写，**单文件 494 KB**（.NET 版是 60 MB），
产出物与 C# 版逐字节同源（同一个 PyInstaller、同一个运行时），
后端自检 24 项全部通过。

## 一、为什么值得重写

| 项 | C# / WPF 版 | C++ 版 |
|---|---|---|
| 主程序体积 | 60.1 MB | **494 KB** |
| 依赖 | 自包含 .NET 运行时 | 仅系统 DLL |
| 冷启动 | 约 1.5 s（自解压） | 约 0.2 s |
| 内存占用 | — | 41 MB |
| 打包产物 | 7.88 MB | 7.89 MB（同一个 PyInstaller） |

C++ 版只依赖这些系统 DLL（`dumpbin /dependents` 实测）：

```
USER32.dll  SHELL32.dll  COMDLG32.dll  ole32.dll
d2d1.dll    DWrite.dll   dwmapi.dll    KERNEL32.dll
```

全部是 Win7 以上自带的，**目标机不需要任何运行时**。

## 二、工具链

这台机器原本没有任何 C++ 编译器。装的是 VS Build Tools（仅 C++ 工具集）：

```
vs_BuildTools.exe --quiet --wait --norestart --nocache \
  --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 \
  --add Microsoft.VisualStudio.Component.Windows11SDK.22621 \
  --includeRecommended
```

得到 MSVC 14.44.35207 + Windows SDK 10.0.22621。

关键编译参数：

- `/MT` —— 静态链接 CRT，否则目标机要装 vcruntime140.dll
- `/utf-8` —— 源码含中文提示文本
- `/SUBSYSTEM:WINDOWS /ENTRY:mainCRTStartup` —— GUI 程序但用 main()

**`build.bat` 必须保持纯 ASCII**：cmd.exe 按系统 ANSI 码页读 .bat，
UTF-8 中文注释会被当成命令执行。这个坑踩过一次，脚本头部有注释说明。

## 三、界面方案 A（分区折叠）的实装

关键约束不是好看，是**一屏装得下**。

主列可视高度 = 窗口 722 − 标题 44 − 动作条 62 = 616 逻辑像素。
脚本卡 + 输出卡 + 构建选项卡必须都在这之内，否则开关会被挤到
可视区之外 —— 用户会以为功能不存在。

按这个反推行高：

```cpp
const float kRowH  = 38.0f;   // 不是随手取的
const float kHeadH = 40.0f;
const float kPadX  = 18.0f;
```

实测布局（125% DPI 下）：

```
脚本卡    y= 62  高 146
输出卡    y=220  高 216
构建选项卡 y=448  高 122      <- 两个开关都在屏内
高级选项  y=582  高 40（折叠态）
```

**「高级选项」（UAC / 清理 / 自检参数 / 超时 / 依赖按钮）默认折叠**，
所以常用项不需要滚动就能全部看到。

自绘而不是用现成控件的原因：Windows 原生控件画不出 iOS 那种圆角与
柔和层次；引 Qt 会把单文件体积从 0.5 MB 推到 10 MB 以上。
Direct2D + DirectWrite 是系统自带的，代价只是自己算布局。

设计令牌与 `Theme.xaml` 完全一致：

```
背景 #000000   卡片 #1C1C1E   输入 #2C2C2E   分隔 #2A2A2C
主色 #0A84FF   成功 #30D158   警告 #FF9F0A   错误 #FF375F
卡片圆角 14     按钮圆角 9     开关 47×28 滑块 24 位移 19
```

## 四、踩到并修掉的坑

### 1. `CreateSolidColorBrush` 的一参重载选不中
`ID2D1RenderTarget` 同时有一参和两参重载，MSVC 不会选一参那个。
包了一层 `Brush(c)` 统一走两参形式。

### 2. 注释以反斜杠结尾会吃掉下一行
`// 反转义：把成对的 \\ 还原成单个 \` 这行让后面的变量声明被注释掉，
报「未声明的标识符」。写成「反斜杠」就没事了。

### 3. 命令行漏了脚本路径
移植时只把脚本用于依赖检查，忘了加进 PyInstaller 参数 →
`pyinstaller: error: the following arguments are required: scriptname`。
后端自检当场抓到。

### 4. PyInstaller 的产物在 `dist\` 子目录
默认 `dist` / `build` 会塞进工作目录，用户看到的不是「输出目录里一个 exe」
而是一堆中间目录。必须显式给 `--distpath / --workpath / --specpath`，
再把 exe 搬到输出目录根。

### 5. 抓屏验证的坐标要对齐客户区
用 `GetWindowRect` 当偏移会带上边框与阴影，所有采样点整体平移。
要用 `ClientToScreen` 拿客户区原点。

## 五、后端自检（44 项全通过）

`tests\run.bat <python.exe> <工作目录>`

```
[1] 依赖检查分类（标准库 / 本地 / 缺失 / 正则粗扫兜底）
[2] 缺依赖必须在打包前被拦下（不进入打包、不产出 EXE）
[3] 正常打包 + 产物自检（产物 7.89 MB，抓到真实输出 {"ok": 1}）
[4] 诊断抽取（缺模块 / hidden import 抽顶层包 / 数据文件 / site-packages 过滤）
[5] 用法错误识别（argparse 缺参数算；缺模块与真实崩溃不算）
[6] 版本号校验（10 项：合法 4 种、非法 6 种）
[7] 版本文件生成 —— 拿真 PyInstaller 的 load_version_info_from_text_file 解析
[8] 打包历史持久化（追加 / 排序 / 字段 / 清理）
[9] 带版本资源的真实打包 —— 打包后从产物里 read_version_info_from_executable
    读回 FileVersion=2.5.1、ProductName=版本测试（中文无损）
```

这三条是从 C# 版带过来的、被真实失败工程钉过的结论：

1. **PyInstaller 对「import 不存在的模块」是哑的** —— 照样返回 0、
   照样产出 exe，坏的只是产物。所以缺模块只能靠产物自检抓到。
2. **补 hidden-import 救不了「模块根本没装」** —— 必须前置拦。
3. **用法错误不是崩溃** —— 需要命令行参数的脚本裸启动必然报 usage，
   当成失败就是误报。

## 六、本轮补齐的功能

| 功能 | 实现要点 |
|---|---|
| 可编辑文本输入 | 自绘光标 / 选区 / Ctrl+A / 拖选 / 横向滚动跟随光标。不用 Edit 控件：混入原生控件会出现字体、圆角、焦点框全不一致 |
| 版本信息对话框 | 五栏（版本号 / 产品名 / 公司 / 描述 / 版权），实时校验，Tab 循环，Enter 确定 / Esc 取消 |
| 版本资源写入 | 按 `VSVersionInfo.__str__` 的结构生成，首行 `# UTF-8`；实测能被 PyInstaller 解析并被产物读回 |
| 一键安装缺失依赖 | 走与打包相同的运行时 + 阿里云镜像，日志实时回灌 |
| 打包历史 | 追加写 `%LOCALAPPDATA%\Dainric\history.txt`，最新在前，独立页面展示 |
| 依赖页表格化 | 模块名 + 状态徽章（已安装 / 缺失），标准库与本地折叠成统计行 |

### 本轮踩到的坑

**输入框的命中区盖住了同一行右侧的按钮。**
输入框的命中矩形是整行宽度（含右侧留给「设置 / 浏览 / 选择」的位置），
而点击处理先判输入框，于是这三个按钮永远点不到。改成按钮优先判定。
这条在 C# 版没出现，因为那边用的是真控件。

**探针不能在观测时改变被测对象。**
为自动化验证加了个「每帧把状态写进窗口标题」的探针，结果标题过长时
Windows 会加高标题栏，客户区尺寸随之变化，布局一直在漂，
自动化测出来的按钮坐标全是负的。改成把探针画在窗口内部才稳定。
