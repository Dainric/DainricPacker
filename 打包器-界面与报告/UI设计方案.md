# Dainric 打包器 — 全新 UI 设计方案

作者：Dainric ｜ 目标版本：v2.9.0 ｜ 原型图：`ui_single.png`、`ui_batch.png`、`ui_compare.png`

## 一、现有界面的 8 个问题

先确认为什么要重做，避免为了换皮而换皮。

| # | 问题 | 证据（v2.8.2 代码位置） |
|---|---|---|
| 1 | **窗口锁死 960×720 不可缩放** | `self.root.resizable(False, False)`；长路径被裁切，批量模式日志区只有 6 行高 |
| 2 | **导航无选中态** | `_nav_btn` 只在 Enter/Leave 变色，当前页与其它页视觉完全一致，用户不知道自己在哪 |
| 3 | **按钮风格不统一** | 同一界面混用 `bg=C_HOVER`（灰）、`C_GREEN`、`C_YELLOW`、`C_RED` 四种实心按钮，主次动作没有层级 |
| 4 | **高级参数与基础配置同级** | `hidden-import` / `add-data` 两个多行文本框常驻，占掉左列约 1/4 高度，而它们 90% 的打包用不到 |
| 5 | **无输入校验反馈** | 输出名非法只在日志区打一行字，输入框本身没有任何提示 |
| 6 | **进度条无阶段语义** | 只有一个百分比数字，用户不知道卡在 Analyzing 还是 Building EXE |
| 7 | **日志与依赖分析挤在一起** | 右列上下堆叠两个 `ScrolledText`，都要抢高度，结果两个都不够看 |
| 8 | **`◈` / `▶` 字形依赖字体** | `◈`(U+25C8) 在部分精简系统/缺字字体下会显示为方框 |

## 二、设计目标

1. **一屏完成主流程** — 选脚本 → 配置 → 打包，不需要滚动
2. **渐进披露** — 高级参数默认折叠，需要时才展开
3. **状态永远可见** — 顶部步骤条告诉你在第几步，底部状态栏告诉你正在干什么
4. **可缩放** — 窗口自由拉伸，日志区跟着长，为主流 1440p / 1080p 都适配
5. **零字体依赖** — 所有图标用 Canvas 矢量绘制，不受系统字体影响
6. **纯 tkinter 可实现** — 不引入 ttkbootstrap / customtkinter 等第三方 UI 库，保持单文件零依赖

## 四、设计 Token

### 配色（对比度已实测，非估算）

```python
# 背景层次
BG        = "#0B0E14"   # 窗口底
ELEV      = "#151A23"   # 卡片
ELEV_2    = "#1C2230"   # 卡片内嵌块 / 次按钮
BORDER    = "#252D3D"   # 常规描边
BORDER_L  = "#323D52"   # 强调描边

# 文字
TEXT      = "#E6EDF3"   # 主文字
DIM       = "#8B98AD"   # 次要文字 / 说明 / 表单标签
MUTE      = "#5F6C82"   # 日志正文 / 时间戳 / 装饰（禁止用于小字号正文）

# 语义色
ACCENT    = "#4C8DFF"   # 主色 / 选中 / 进度
ACCENT_BG = "#16243D"   # 主色浅底
OK        = "#3FB950"   # 成功
WARN      = "#D29922"   # 进行中 / 警告
ERR       = "#F85149"   # 失败 / 危险操作
```

**实测对比度**（脚本 `check_contrast.py`，WCAG 相对亮度公式）：

| 前景 | 背景 | 对比度 | AA 正文 4.5:1 | 用途约束 |
|---|---|---|---|---|
| TEXT `#E6EDF3` | ELEV | **14.76** | ✅ | 任意 |
| TEXT `#E6EDF3` | BG | **16.35** | ✅ | 任意 |
| DIM `#8B98AD` | ELEV | **5.97** | ✅ | 任意 |
| ACCENT `#4C8DFF` | ELEV | **5.45** | ✅ | 任意 |
| OK `#3FB950` | ELEV | **6.87** | ✅ | 任意 |
| WARN `#D29922` | ELEV | **6.91** | ✅ | 任意 |
| ERR `#F85149` | ELEV | **5.20** | ✅ | 任意 |
| MUTE `#5F6C82` | ELEV | **3.28** | ❌ | 仅 ≥14px 粗体或纯装饰 |
| MUTE `#5F6C82` | ELEV_2 | **2.99** | ❌ | ❌ 连大字也不达标 |

> **MUTE 的使用红线**：实测 `MUTE` 在卡片底上只有 3.28:1，在 `ELEV_2` 上只有 2.99:1。
> 因此它**只能**用在两类地方：(1) 日志正文/时间戳这类"长文本、可容忍低对比"的内容；
> (2) 纯装饰性元素（分隔线、未激活图标）。
> 所有**表单标签、说明文字、单位后缀**必须用 `DIM`（5.97:1）。
> 旧代码把 `#8b949e`（5.62:1）用在这些位置是达标的，**改成 MUTE 反而是退步**——这点必须按上表执行。

**关于层次感**：卡片与背景的亮度差，旧方案 0.52%、新方案 0.58%，差别很小。
真正的层次感来自 **1px 描边（`BORDER`）+ 12px 间距 + 圆角**，而不是靠亮度差硬拉。
不要指望调背景色就能解决层次问题。

**与旧色的取舍**：旧 `TEXT #c9d1d9` 对比度 11.21，新的 `#E6EDF3` 是 14.76，更亮更清晰；
但旧的次级色 `#8b949e` 是 5.62，比新 `MUTE` 的 3.28 更安全——所以**次级文字一律沿用 `DIM`**，
`MUTE` 只承担日志与装饰，不承担信息传达。

### 字体

```python
FONT_UI    = ("微软雅黑", 10)          # 正文
FONT_UI_SM = ("微软雅黑", 9)           # 辅助
FONT_H1    = ("微软雅黑", 16, "bold")  # 应用名
FONT_H2    = ("微软雅黑", 13, "bold")  # 卡片标题
FONT_MONO  = ("Consolas", 10)          # 日志/路径/命令
FONT_MONO_S= ("Consolas", 9)           # 日志时间戳
```

旧代码用 `微软雅黑 14 bold` 做标题偏大、`Consolas 10` 与中文混排时行高跳动；新方案固定**日志行高 18px** 保证等宽对齐。

### 间距

`4 / 8 / 12 / 16 / 24` 五档。卡片内边距统一 `16`，卡片间距统一 `12`，圆角统一 `R=10`（小控件 `R=7`，胶囊 `R=高度/2`）。

## 五、核心组件

### 1. Card（卡片）
tkinter 没有原生圆角+描边，用 **Canvas 打底 + Frame 内嵌** 实现：

```python
class Card(tk.Frame):
    """圆角卡片容器：Canvas 画背景，内层 Frame 承载内容"""
    def __init__(self, parent, title=None, collapsible=False, r=10):
        super().__init__(parent, bg=C_BG)
        self.canvas = tk.Canvas(self, bg=C_BG, highlightthickness=0)
        self.canvas.pack(fill="both", expand=True)
        self.inner = tk.Frame(self.canvas, bg=C_ELEV)
        self._win = self.canvas.create_window(16, 16, window=self.inner, anchor="nw")
        self.canvas.bind("<Configure>", self._redraw)
```

`_redraw` 里先 `delete("bg")`，再用 `create_polygon(..., smooth=True)` 画圆角矩形（和现有 `DarkButton._rounded_rect` 同思路，已验证可用），最后 `tag_lower("bg")` 压到内容下面。滚动/缩放时重画即可。

### 2. 按钮三级层次

| 级别 | 用途 | 样式 |
|---|---|---|
| Primary | 开始打包 | `ACCENT` 实底 + 白字，hover `#3D7BE8`，press `#2F6BE0` |
| Secondary | 浏览 / 更换 / 打开目录 | `ELEV_2` 底 + `BORDER_L` 描边 + `TEXT` 字，hover `#232B3B` |
| Danger | 清空 / 停止 | 透明底 + `ERR` 描边 + `ERR` 字，hover 填 `#2A1518` |

旧代码把 `清空` 做成红色实心按钮，视觉重量和 `开始打包` 一样重，是明显的层级错误。

统一改用现有 `DarkButton`（Canvas 自绘）即可支持圆角+描边，补上 `press` 态和 `disabled` 态（`fg=MUTE`、不响应 hover）。

### 3. StepBar（步骤条）
纯 Canvas 绘制：实心圆(当前/已完成) → 22px → 数字 → 文字 → 24px 连接线。
点击已完成步骤可跳回，未解锁步骤置灰不可点。

### 4. LogView（日志）
在现有 `_append_log` 基线上增强：
- 左侧时间戳列固定 62px（`FONT_MONO_S`，`MUTE`），右侧正文用 `TAG` 上色
- 按内容自动配色：`[+]`→OK，`[-]`→ERR，`[*]`→DIM，`INFO:`→MUTE，命令行→ACCENT
- **保留**现有那个很好的行为：仅当 `yview()[1] >= 0.99` 时才 `see("end")`，用户翻历史不被打断
- 顶部工具条：`清空` / `复制全部` / `自动滚动` 开关

### 5. 输入框校验态
`DarkEntry` 增加 `set_state("normal"|"error"|"ok")`，切换描边色：
- 正常 `BORDER` ／ 聚焦 `ACCENT` ／ 校验失败 `ERR` + 下方 9px 红字提示

输出名失焦即校验 `_is_valid_out_name()`，非法立刻变红并给出原因（"含非法字符" / "系统保留名" / "不能以点结尾"），不再只写日志。

## 六、必须改掉的具体行为

| 项 | 现在 | 改为 |
|---|---|---|
| 窗口 | `geometry("960x720")` + `resizable(False, False)` | `geometry("1180x780")` + `minsize(980, 640)`，左右列按 `weight` 分配 |
| 导航 | 三个 Label 手绑 Enter/Leave | StepBar，带选中态 |
| 高级参数 | 常驻两个多行 Text | 折叠卡片，展开后显示；折叠时标题右侧显示"已设置 N 项" |
| 日志 | 底部大框 + 右列小框，双份 | 只留右列，Tab 切换 日志/依赖/文件信息 |
| 依赖分析 | 常驻右列上方 | 移到 Tab 页，打包时自动切到"日志" |
| 进度条 | 全局独立一条 | 移到日志面板底部，加阶段名 + 耗时 |
| 图标字形 | `◈` `▶` | Canvas 矢量图标 |
| 状态栏 | 纯文字 `就绪` | 左侧状态点 + 文字，右侧实时耗时 |

## 七、DPI 适配（旧版完全没做）

```python
# 启动时按显示器缩放设置 Tk 缩放，避免 150% 缩放下界面糊/错位
try:
    from ctypes import windll
    windll.shcore.SetProcessDpiAwareness(1)
except Exception:
    pass
scale = root.winfo_fpixels("1i") / 96.0
root.tk.call("tk", "scaling", scale * 1.333)
```

不处理的话，在 125%/150% 缩放的笔记本上，`font=("微软雅黑", 10)` 会渲染得偏小且控件间距错乱——这是 Windows 高分屏最常见的观感问题。

## 八、实施顺序（建议分 3 步提交）

1. **骨架**：Token 常量 + `Card` 组件 + 新布局（步骤条 / 双列 / 底部操作栏）+ `resizable` + DPI
2. **组件**：三级按钮、`DarkEntry` 校验态、`LogView` 着色、Tab 面板、矢量图标
3. **行为**：折叠高级参数、失焦校验、阶段化进度、日志工具条

第 1 步完成后界面就已经和原型一致，第 2、3 步是打磨。

## 九、兼容性说明

- **不引入第三方 UI 库**，仍然单文件、`tkinter` only，打包脚本本身不需要额外依赖
- 现有业务逻辑（`do_pack`、`run_command`、依赖分析、批量队列、v2.8.2 的全部修复）**完全不动**，只替换视图层
- 深色为主，Token 已按可换肤方式命名，后续要加浅色主题只需替换那一组常量
